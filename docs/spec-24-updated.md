## Spec: Fix llama-cpp-sys-2 Build Failure on Windows

### Overview

\cargo build\ fails on Windows because \.cargo/config.toml\ line 15 explicitly sets \CMAKE_GENERATOR = \"Visual Studio 17 2022\"\. CMake 4.3 with the Visual Studio generator fails to produce \.vcxproj\ target files, causing \cmake --build ... --target install\ to fail with \MSB1009: Project file does not exist\.

The fix: change \CMAKE_GENERATOR\ from \Visual Studio 17 2022\ to \Ninja\ in \.cargo/config.toml\.

### Architecture Decisions

- **DEC-1**: Use Ninja as the CMake generator. It is already available on the system and produces faster, more reliable builds on Windows.
- **DEC-2**: The change is a single-line edit to an existing file — no new files needed.

### Requirements

- **REQ-1**: When \cargo build\ is run on Windows, the \llama-cpp-sys-2\ crate **shall** use Ninja as its CMake generator.
- **REQ-2**: When \cargo build\ is run on Unix/macOS, the build **shall** continue working without changes (Ninja is cross-platform).
- **REQ-3**: The \llama-cpp-2\ crate version and features **shall** remain unchanged.
- **REQ-4**: After the fix, \cargo build\ from \^Gpps/tauri/src-tauri/\ **shall** complete successfully with zero errors from \llama-cpp-sys-2\.

### Root Cause Analysis

\.cargo/config.toml\ line 15 sets \CMAKE_GENERATOR = \"Visual Studio 17 2022\"\. CMake 4.3 with this generator fails to produce \.vcxproj\ files when invoked from a Cargo build script. The Ninja generator doesn't use \.vcxproj\ files and works reliably.
