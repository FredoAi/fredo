# Event persistence (per-contract store + hydration) functional tests

Derived from the #2768 QA Plan (verification policy: live — every PASS requires `telemetry_spans` evidence; receipts key on real `ses_*` ids, G-076; span-stability after completion, G-079).

- [x] F-1 (AC2) Hydrate full history after full-session absence: drive a ≥2-subagent Run CLI session to completion with Mission Monitor never opened → span-stability check → open Mission Monitor. Expected: complete graph (main node + prompt + reply + every SubagentNode with parent edges); node set identical to the live baseline captured for the same real `ses_*`. Edge: first-ever open with empty contract history — empty/no-graph state, no crash, no console error; for a session WITH persisted history the "No Agent Sessions Yet" / "Select a session…" empty-state must NEVER flash (spinner → blank canvas → framed graph ladder).
  - VERIFIED round 1 (F4B full-absence hydration PASS, G-079-stable) and re-demonstrated round 2: F5 re-rendered with an IDENTICAL node-id set after two cold restarts + two prune cycles.
- [ ] F-2 (AC3) Partial-window gap fill: open Mission Monitor at session start → after the first SubagentNode appears, close it → let the session complete → span-stability check → reopen. Expected: nodes emitted during the closed window are present; full node set equals the live baseline for the same `ses_*`. Edge: multiple close/reopen windows (union complete); close mid-subagent-stream (node completes after reopen, no half-rendered node).
  - ROUND 2: components live-verified on R2B (node witnessed 03:27:28.4, close with unmount 03:27:46, reopen full graph, zero duplicates) BUT zero emissions landed in the closed window (tree completed 03:27:26, pre-close — `sleep 20` failed under PowerShell, see exploratory E-8). Strict component remains UNEXERCISED after 2-drive budget; next attempt must use `Start-Sleep -Seconds N` inside the subagent tool call.
- [x] F-3 (AC4) Store bounded + policy documented: set the retention cap small via the documented knobs (`contracts.retention_days`, `contracts.max_rows`) → drive sessions until more contract events persist than the cap → await/trigger pruning. Expected: row count in the `contract_events` table ≤ cap; docs state what is kept, for how long/how much, and how to configure. Edge: exactly-at-cap boundary (newest event not dropped off-by-one); hydrating a partially pruned session renders only retained events, no error.
  - VERIFIED round 2, LIVE ×2: 6540 → exactly 6420 (min seq 1 → 131) and 6420 → exactly 5620 (min seq → 957) — count == cap both cycles, oldest-first. Knob written via the app's own `save_setting` IPC (documented test write, restored to 100000). Pruned-session hydration: F5 renders complete retained graph from the FeatureStore with zero errors after its contract rows were fully pruned.
- [x] F-4 (AC6) Generic per-contract store serves a non-Mission-Monitor contract: drive events matching the stepper-probe contract (`Fredo_ui_stepper`, persistent) while its consumer is closed → open the consumer. Expected: the non-MM consumer hydrates its persisted events from the shared store (no MM-specific path); observed content/count matches `telemetry_spans`. Edge: contract with no persisted history — empty state, no error; two contracts matching the same event persist/read independently.
  - VERIFIED round 1 (hydrated 4 deliveries; empty-history edge PASS). Round 2: no MM-coupling regression from the 4a9361e frontend fix (no shared code paths touched).
- [x] F-5 (NFR-DUPE) Hydration dedupe on reopen: open Mission Monitor → close → reopen ×2 comparing node-id sets. Expected: every node/event appears exactly once after each reopen; identical counts across reopens; no duplicate-key console warnings. Edge: rapid successive reopens; hydration racing a live update delivery (init vs update ordering after reopen mid-session). Diagnostic aid: hydrate helper returns injected-row count; `contract_events_hydrate` emits a per-contract `tracing::debug!`.
  - VERIFIED round 1 (F5 ×2) and round 2 on the fixed collector (identical node-id sets, zero duplicate-key warnings, chip deterministic 0 both reopens).
- [x] F-6 (NFR-HOTP) Persistence does not delay live delivery: with Mission Monitor open during a live session, correlate each SubagentNode's UI-appearance time with the underlying span timestamp. Expected: p95 delta ≤ 2s; no visible stall during persist; no long-task/blocking console errors. Edge: end-of-session span flush burst (G-079) — UI stays responsive during the batch.
  - ROUND 2: single sample 1.839 s ≤ 2 s (R2B: FeatureStore node-creating-delivery arrival 03:27:17.7712024 − task span start 03:27:15.932). n=1 — p95 depth needs more drives than the 2-drive budget allows; no violation observed. Measurement method: see smoke S-7.
- [x] F-7 (NFR-RET) Pruning is automatic and oldest-first: exceed the retention cap multiple times, re-check store size after each excess without manual maintenance. Expected: size stays ≤ cap; pruned ids are the earliest; no manual command required. Edge: pruning does not remove events still needed by an OPEN feature's live window (per documented policy).
  - VERIFIED round 2: startup prune exercised twice live (identical prune() path); interval leg = static receipt (store.rs WRITER_PRUNE_INTERVAL 60 min, knobs re-read each cycle) + standing unit tests (oldest-first, exactly-at-cap). FeatureStore survives contract pruning (round-2 live — see exploratory E-7).
