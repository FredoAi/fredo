# Event persistence (per-contract store + hydration) functional tests

Derived from the #2768 QA Plan (verification policy: live — every PASS requires `telemetry_spans` evidence; receipts key on real `ses_*` ids, G-076; span-stability after completion, G-079).

- [ ] F-1 (AC2) Hydrate full history after full-session absence: drive a ≥2-subagent Run CLI session to completion with Mission Monitor never opened → span-stability check → open Mission Monitor. Expected: complete graph (main node + prompt + reply + every SubagentNode with parent edges); node set identical to the live baseline captured for the same real `ses_*`. Edge: first-ever open with empty contract history — empty/no-graph state, no crash, no console error; for a session WITH persisted history the "No Agent Sessions Yet" / "Select a session…" empty-state must NEVER flash (spinner → blank canvas → framed graph ladder).
- [ ] F-2 (AC3) Partial-window gap fill: open Mission Monitor at session start → after the first SubagentNode appears, close it → let the session complete → span-stability check → reopen. Expected: nodes emitted during the closed window are present; full node set equals the live baseline for the same `ses_*`. Edge: multiple close/reopen windows (union complete); close mid-subagent-stream (node completes after reopen, no half-rendered node).
- [ ] F-3 (AC4) Store bounded + policy documented: set the retention cap small via the documented knobs (`contracts.retention_days`, `contracts.max_rows`) → drive sessions until more contract events persist than the cap → await/trigger pruning. Expected: row count in the `contract_events` table ≤ cap; docs state what is kept, for how long/how much, and how to configure. Edge: exactly-at-cap boundary (newest event not dropped off-by-one); hydrating a partially pruned session renders only retained events, no error.
- [ ] F-4 (AC6) Generic per-contract store serves a non-Mission-Monitor contract: drive events matching the stepper-probe contract (`Fredo_ui_stepper`, persistent) while its consumer is closed → open the consumer. Expected: the non-MM consumer hydrates its persisted events from the shared store (no MM-specific path); observed content/count matches `telemetry_spans`. Edge: contract with no persisted history — empty state, no error; two contracts matching the same event persist/read independently.
- [ ] F-5 (NFR-DUPE) Hydration dedupe on reopen: open Mission Monitor → close → reopen ×2 comparing node-id sets. Expected: every node/event appears exactly once after each reopen; identical counts across reopens; no duplicate-key console warnings. Edge: rapid successive reopens; hydration racing a live update delivery (init vs update ordering after reopen mid-session). Diagnostic aid: hydrate helper returns injected-row count; `contract_events_hydrate` emits a per-contract `tracing::debug!`.
- [ ] F-6 (NFR-HOTP) Persistence does not delay live delivery: with Mission Monitor open during a live session, correlate each SubagentNode's UI-appearance time with the underlying span timestamp. Expected: p95 delta ≤ 2s; no visible stall during persist; no long-task/blocking console errors. Edge: end-of-session span flush burst (G-079) — UI stays responsive during the batch.
- [ ] F-7 (NFR-RET) Pruning is automatic and oldest-first: exceed the retention cap multiple times, re-check store size after each excess without manual maintenance. Expected: size stays ≤ cap; pruned ids are the earliest; no manual command required. Edge: pruning does not remove events still needed by an OPEN feature's live window (per documented policy).
