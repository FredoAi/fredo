# workspace-layout — Exploratory Probes

Unscripted edge/failure probes for the zone model (issue #2980, replacing the 9-region arrangement UX #2949). A CONFIRMED finding PROMOTES to `functional.md` as a new `F-` case (keep the origin note). Drive via `pnpm dev:tauri`; confirm the target pane/window via DOM before each capture; read the webview console after every probe. Live policy: include the `telemetry_spans` reference with the round evidence.

## Probes to run beyond the script

- [ ] E-1 (OPEN — custom-split recursion depth + fractional preview fidelity): in `layout-editor` build a `custom` layout by repeatedly selecting a zone and splitting it (`layout-editor-split-h`/`-v`) several levels deep. Do the preview tiles stay gap-free/fraction-exact (the rendered zones tile the preview with no overlap, gap, or negative size), and does recursion depth degrade gracefully (no throw, no runaway)? A drifted/overlapping preview or a deep-split throw is a finding (promotes to F-1).
- [ ] E-2 (OPEN — edit the ACTIVE layout while windows are zoned): enable + assign a layout, zone two windows, then `layout-edit-<id>`, change its zones, confirm. Do the zoned windows re-derive to the new zones without corruption or throw (R-2.5), with sibling zones intact and console clean? A stale rect, corrupted pane, or draft-only change leaking early is a finding (promotes to F-2).
- [ ] E-3 (OPEN — delete the active layout): with a layout active and windows zoned, delete it via `layout-delete-<id>`. Do dependent assignments clear ATOMICALLY (no partial state), do freed windows return to free float, and does the next restart stay clean (no resurrected layout)? A half-cleared assignment, a crash, or a resurrected layout is a finding (promotes to F-3).
- [ ] E-4 (OPEN — no-zone release / Escape mid-drag): chord-drag a window and release over an inter-zone gap and outside the workspace; repeat pressing Escape mid-drag. Is geometry UNCHANGED, is no assignment written, does focus stay where it was (not moved/trapped), and is the console clean? A geometry write, a focus steal, or a throw is a finding (promotes to F-4).
- [ ] E-5 (OPEN — persisted assignment to an unregistered/closed window): seed `Fredo_layout_zones` via `tauri_ipc_execute_command('save_setting',…)` with an assignment whose `windowId` is unregistered, restart, read back with `get_setting`. Does its zone render `zone-degraded-<windowId>` (or `workspace-empty-slot-*` when minimized) with the sibling zones/windows UNCHANGED and nothing throwing? A dropped sibling, a crash, or a lost assignment is a finding (promotes to F-5).
- [ ] E-6 (OPEN — restart during an active chord-drag / app kill): kill the app mid-chord-drag (no graceful close), relaunch. Does boot hydrate the last PERSISTED config/assignments without throwing, and is the transient drag state (`dragActive`/`hoveredZoneId`) never persisted? A blank/partial workspace or a stale `dragActive:true` in storage is a finding (promotes to F-6).
- [ ] E-7 (OPEN — theme/accent flip mid-chord-drag): start a chord-drag, flip Classic↔Turbo (or the user accent) mid-drag, release. Do the overlay, zone targets, and zoned panes re-tint without a layout jump, and does the gesture complete? A stale color or a geometry reset is a finding (promotes to F-7).
- [ ] E-8 (OPEN — zero-zone layout editor): open `layout-editor` and remove every zone. Is `layout-editor-confirm` DISABLED (with an explanation), and is assigning a zero-`zones[]` layout refused (`layout-assign-<id>` disabled; `setActiveZoneLayout` no-op, no throw, no active change)? A confirmable empty layout or an active zero-zone layout is a finding (promotes to F-8).
- [ ] E-9 (OPEN — many zones / narrow viewport): define a layout with many zones and assign many windows; repeat in a narrow viewport. Do all panes remain reachable (no off-workspace pane, no zero-size pane — clamped ≥320×200), and is the persisted payload ≤ 16 KB? A clipped/unreachable or zero-size pane is a finding (promotes to F-9).
- [ ] E-10 (OPEN — corrupt/unknown persisted value + legacy purge): pre-seed `Fredo_layout_zones` with malformed JSON and an unknown `version`, and pre-seed the legacy `Fredo_workspace_layout`. Reload each. Does the app boot to a clean desktop (or graceful defaults) with the legacy key purged (never migrated) and the console clean? A throw on mount or a resurrected legacy arrangement is a finding (promotes to F-10).
- [ ] E-11 (OPEN — reduced motion): with `prefers-reduced-motion: reduce`, is the `zone-overlay` appear/hover transition subtle (opacity only, no distracting animation)? A jarring animation is a finding (promotes to F-11).
- [ ] E-12 (OPEN — accessibility tree): snapshot the a11y tree during a chord-drag. Is `zone-overlay` non-focusable with no focusable children, is there EXACTLY ONE `zone-announcer` live region (`role="status" aria-live="polite"`), and are the editor controls labelled (template `radiogroup` with `aria-checked`, preview zones `aria-pressed` + "Zone k of n", nav item `aria-current="page"`)? A focus-stealing overlay, a missing/duplicate announcer, or an unlabelled control is a finding (promotes to F-12).
