# Git Operations — fredo-tester

## Branch Workflow

### Work on Coder's Branch

```bash
# Fetch the coder's branch
git fetch origin
git checkout -b test/<feature-name> origin/feature/<feature-name>
```

### Create Test Branch

```bash
# If working independently
git checkout main
git pull origin main
git checkout -b test/<short-description>
```

### Branch Naming

| Type | Format | Example |
|------|--------|---------|
| Tests for feature | `test/<feature-name>` | `test/dark-mode-toggle` |
| Test fixes | `fix/<test-description>` | `fix/flaky-e2e-test` |

## Commit Workflow

### Scope: Tests Only

You should **only modify test files**. Never modify production code.

```bash
# Stage test files only
git add **/*.test.ts
git add **/*.spec.ts
git add tests/

# Verify what's staged
git diff --cached --name-only
```

### Commit Messages for Tests

```
test(ui): add e2e tests for dark mode toggle
test(llm): add unit tests for connection retry logic
fix(test): fix flaky companion positioning test
```

### Amend Last Commit

```bash
# Add forgotten test files
git add forgotten-test.test.ts
git commit --amend --no-edit
```

## Push and PR Workflow

### Push Test Branch

```bash
git push -u origin test/<branch-name>
```

### Create DRAFT PR

```bash
# Always create DRAFT PRs
gh pr create --draft --title "test: <short description>" --body-file pr-body.md

# Add labels
gh pr edit --add-label "test"

# Assign reviewers
gh pr edit --add-reviewer pktron
```

### PR Body Template

```markdown
## Test Plan

- [ ] E2E: <test description> — verifies REQ-1, REQ-2
- [ ] E2E: <test description> — verifies REQ-3
- [ ] Unit: <test description> — covers edge case for REQ-4

## Requirements Coverage

| Requirement | Test File | Status |
|-------------|-----------|--------|
| REQ-1 | path/to/test.test.ts | Covered |
| REQ-2 | path/to/test.test.ts | Covered |

## Test Results

- Tests added: <count>
- Tests passing: <count>
- Tests failing: <count>

## Bugs Discovered

<List any bugs found, or "None">

## Confidence Level

<High/Medium/Low — with reasoning>

---
*Generated by @fredo-tester*
```

## Running Tests

### Run Full Test Suite

```bash
# Run all tests
npm test

# Or project-specific
pnpm test
```

### Run Specific Tests

```bash
# Run specific test file
npm test -- path/to/test.test.ts

# Run tests matching pattern
npm test -- --grep "dark mode"
```

### Verify No Regressions

```bash
# Always run full suite before pushing
npm test

# Check for lint issues
npm run lint

# Type check
npm run typecheck
```

## Common Operations

### Pull Latest Coder Changes

```bash
# If coder pushed new commits to the branch
git fetch origin
git rebase origin/feature/<feature-name>
```

### Check Test-Only Changes

```bash
# Verify only test files are modified
git status
git diff --name-only
```

### Stash Test Work

```bash
git stash push -m "WIP tests: <description>"
git stash list
git stash pop
```

## Constraints

- **Always open DRAFT PRs** — never ready for review
- **Do not modify production code** — only add/modify test files
- **If tests reveal bugs in production code**, comment on the issue and stop
- **Run the full test suite** to ensure no regressions
- **Document any skipped tests** and why
- **Map every test to at least one EARS requirement** (REQ-X)
- **Fill the Test Plan section** into the spec issue before writing tests
