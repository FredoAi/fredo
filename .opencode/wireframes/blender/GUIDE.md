# How FREDO's avatar works, and how to change it

A practical guide to the companion avatar: how it is put together, how to
preview it, and how to add or edit states, clothing, props and colours.

- **This file** — how to use and edit.
- [`STYLE_RULES.md`](./STYLE_RULES.md) — the art-direction rules (style, colour, clips).
- [`ASSET.md`](./ASSET.md) — the technical handoff contract (units, clip table).

---

## 1. What it is

One character, exported as a single `.glb` for a web runtime:

- **one skinned mesh** (~42k triangles, quads, rigid weights)
- **one skeleton** (77 bones: body joints, face shapes, props, wardrobe)
- **32 animation clips** at 12 fps
- **17 materials**, one per object group

Everything is generated by `build_character.py` from two inputs: the rectangle
list in `../fredo-avatar.html` and the geometry definitions inside the builder.
There is no hand-edited `.blend` — the `.blend` is an output.

## 2. Files

```
.opencode/wireframes/blender/
├── fredo-character.glb            the asset (ship this)
├── fredo-character.manifest.json  runtime contract, generated from the GLB
├── fredo-character.blend          source scene (output, not hand-edited)
├── build_character.py             THE builder - all geometry, bones, clips
├── blender_client.py              talks to Blender over the addon socket
├── render_clips.py                renders preview stills
├── export_manifest.py             regenerates the manifest from the GLB
├── inspect_glb.py                 validates the GLB container
├── preview.html                   interactive viewer (clips, views, zoom, colour)
└── previews/                      rendered stills + contact sheets
```

## 3. Prerequisites

Blender running with the official Lab MCP add-on listening on `127.0.0.1:9876`
(Add-on → **Start MCP Server**). The builder is a plain Python string sent over
that socket — no MCP client needed, `blender_client.py` is enough.

## 4. Preview it

```powershell
cd C:\Code\fredo
python -m http.server 8099 --bind 127.0.0.1
```

Open `http://127.0.0.1:8099/.opencode/wireframes/blender/preview.html`.

- click clips to crossfade, or `1`–`9` / `0`
- **VIEW** buttons: front / 3/4 / side / back / low / high
- **ZOOM** slider + number (metres)
- **COLOUR**: presets and a per-material picker
- type `doom` for the secret mode, `Esc` to leave

## 5. The design model

Everything is authored in a **1014 × 1264 reference canvas** (the same space as
`fredo-avatar.html`), then converted to metres:

```python
S = (1234 - 67) / 1.8          # reference px per metre (~648)
wx(x) = (x - 507) / S          # canvas X  -> world X
wz(y) = (1234 - y) / S         # canvas Y  -> world Z (Y is down in canvas)
```

Ground is `y = 1234`, the head top is `y = 67`, the character is 1.8 m tall.

Three construction styles coexist (see STYLE_RULES §1):

| Style | Function | Looks like |
|---|---|---|
| Voxel | `add_slabs(bone, slabs, depth, bevel, material, y_offset)` | Fredo's body, wardrobe |
| Plated 3D | `add_prim(bone, maker, material)` | Doom armour |
| 2D drawn | not implemented yet | future |

Plated 3D gear is built from lofted shells, extruded chamfered outlines
(`_append_plate`) and shell patches (`_patch`); see the "DOOM ARMOUR" block in
the builder for the helpers and the reasoning.

## 6. Edit an existing state

Clips live in `build_clips()` in `build_character.py`. Each is a function that
calls `key(bone, frame, rot=, loc=, scale=)`.

```python
def happy():
    eyes("arc")                                  # which eye shape
    for f, dz, sq in ((1, 0, 1.0), (4, 0.055, 1.06), (8, 0, 1.0), (L, 0, 1.0)):
        key("root", f, loc=(0, 0, dz), scale=(sq, 1, 2 - sq))
    key("head", 1, rot=(0, 3, 0))
    key("head", 8, rot=(0, -3, 0))
```

- frames are 1‥16 (`L` = 16), 12 fps ≈ 1.33 s
- rotations are **degrees**; `rot=(nod, turn, tilt)`
- **the last key must repeat the first pose** or the loop pops

## 7. Add a new state

1. Write the function inside `build_clips()`.
2. Register it: `out["sleepy-eat"] = sleepy_eat` (name == state name, kebab-case).
3. Pick the face with `eyes(...)`: `"open"`, `"none"`, or `arc / chev / round / lid / heart / sad`.
4. Show objects with `show_bone("hat", (1, L))` and `show_prop("thinking", (2, L))`.
5. Rebuild (§10), then refresh the viewer — the clip appears automatically.

Rules that bite if skipped:

- every clip must key **every animated bone** at rest first (the builder does
  this automatically in the clip loop — do not remove it)
- props and wardrobe are hidden automatically in every clip; reveal what you want
- one-shot clips must be added to `ONE_SHOT` in `preview.html` and to
  `NON_LOOPING` in `export_manifest.py`

## 8. Add an object (hat, monocle, weapon, prop)

1. Define its geometry in reference space:

```python
MY_PROP = [(400.0, 200.0, 60.0, 40.0), (460.0, 180.0, 40.0, 60.0)]
```

2. Register it with a bone, a parent joint and a material:

```python
EXTRA_BONES["my_prop"] = ((430.0, 220.0), "head", MY_PROP, "fredo_metal")
```

`EXTRA_BONES` are **hidden by default** — reveal with
`show_bone("my_prop", (1, L))` inside the states that want it.

3. For smooth 3D instead of voxels, use `EXTRA_PRIMS`:

```python
EXTRA_PRIMS["helmet"] = ((507.0, 340.0), "head",
                         _mk_ellipsoid((0.0, 0.02, HELM_Z), (0.60, 0.42, 0.46)),
                         "fredo_helm")
```

## 9. Colours

Every object group has its **own material**, declared once in the palette:

```python
PALETTE = [
    ("fredo_body",   (1.0, 1.0, 1.0), 1.00),   # white -> tinted at runtime
    ("fredo_metal",  (0.85, 0.66, 0.22), 0.85),  # brass
]
```

- Body-ish materials stay **white**: the app tints them to the user's colour.
- Wardrobe ships its intended colour.
- Switching palettes at runtime (doom mode) is a material colour change, never
  new geometry — see `DOOM_PALETTE` in `preview.html`.
- Adding a material means adding it to the palette table in `ASSET.md` too.

## 10. Rebuild and verify

```powershell
python blender_client.py build_character.py     # geometry + bones + clips + GLB
python blender_client.py render_clips.py        # preview stills
python export_manifest.py                       # manifest from the GLB
python inspect_glb.py                           # container check
```

`inspect_glb.py` must report: **1 mesh, 1 skin, 0 cameras, 0 unskinned nodes**,
and the expected clip count. Anything else means the export regressed.

## 11. Bringing in an external 3D model

A marketplace, commissioned or original model can replace the procedural armour
without touching the rig:

1. Drop the `.glb` into this folder.
2. Import into Blender and scale so the character is 1.8 m with the origin at
   ground level.
3. Add a **vertex group named after the target bone** (`helmet`, `head`, `body`,
   `gun`) and assign every vertex weight `1.0` — rigid skinning, no blending.
4. Give it its **own material** so it stays independently tintable.
5. Reveal it only in the `doom-*` clips via `show_bone`.
6. Rebuild; `inspect_glb.py` must still report 1 mesh / 1 skin.

> **Licensing:** Doomguy is id Software IP, so a model ripped from the games
> cannot ship in Fredo. A GitHub API search for free Doomguy models returns
> essentially nothing usable (one unlicensed gloves/weapons repo), so this is
> commission-or-build territory in practice.

## 12. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Dark square on a part | overlapping or face-to-face voxel tiles (z-fighting) | keep tiles non-overlapping; `seams()` adds the gap |
| A state inherits a previous state's expression | a bone was not keyed in that clip | the clip loop normalises all bones — don't bypass it |
| Colour changes don't apply | Blender suffixed the material (`fredo_body.001`) | the builder purges `fredo*` materials before rebuilding |
| Prop visible in every state | it is in `EXTRA_BONES` but never hidden | it is hidden by default; check you did not remove it from `HIDE_BONES` |
| Prop clipped by the frame edge | geometry outside the camera's ortho box | move it inward, or widen `ortho_scale` |
| Loop stutters | last key ≠ first key | repeat the first pose on frame `L` |
| An object ignores your edit | a **later function with the same name** silently shadows yours | `grep -n "^def _mk_" build_character.py`; `py_compile` compiles fine either way |

## Mental model

**Bones carry motion, materials carry colour, clips carry states.** Geometry is
just something attached to a bone and shaded by a material. That is why a new
hat, a new mood or a whole alternate art style can all be added without touching
the rig, the runtime, or any existing state.
